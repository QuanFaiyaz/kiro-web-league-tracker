# Match ordering indicators and UI polish

The change adds temporal context to match history cards — match number badges, "Most Recent" labels, and relative timestamps — so users can immediately tell which games are newest without counting positions. A `gameStartTimestamp` field flows from the Riot API through the route handler into the client, where a new `formatTimeAgo` utility renders it as human-readable relative time. Alongside the functional work, visual polish was applied across the header, search form, region selector, and card components (gradient backgrounds, ring focus states, transitions).

**Watch for:** Unused `totalMatches` prop accepted but never read (confirmed, dead code). Overflow badges positioned outside card boundaries depend on parent grid gap for visibility (possible).

## High-level view

The timestamp is extracted with a fallback chain (`gameStartTimestamp || gameCreation || Date.now()`). The `Date.now()` terminal fallback means if both Riot fields are absent, the match will misleadingly display "just now" — a conservative fallback of `0` with an "unknown" display would be safer, though the Riot API reliably provides at least one of these fields.

The MatchCard layout introduces absolute-positioned badges that overflow the card boundary (`-top-2 -left-2`). This works with the current `gap-3` grid, but is fragile if spacing changes or a parent adds `overflow-hidden`.

`totalMatches` is defined in `MatchCardProps`, passed from `MatchHistory`, but never destructured or used inside `MatchCard`. Dead code.

## Timestamp fallback and misleading "just now"

The API route uses `match.info.gameStartTimestamp || match.info.gameCreation || Date.now()`. Because JavaScript's `||` operator treats `0` as falsy, a timestamp value of `0` (epoch) would also trigger the fallback chain — though the Riot API doesn't return `0` for these fields in practice. The real concern is the `Date.now()` terminal fallback: if both fields are genuinely missing (API schema change, partial response), every match in the batch gets the same "just now" timestamp, destroying the ordering signal this feature was built to provide.

## `formatTimeAgo` weeks-to-months boundary

The weeks threshold (`weeks < 5`) means a 34-day-old match displays "4 weeks ago" while a 35-day-old match jumps to "1 month ago". The transition is slightly abrupt — a match played 4.5 weeks ago shows as "4 weeks" while one played 5 weeks ago shows "1 month". Not a bug, but worth knowing if users report confusing time labels.

## Accessibility of badge overflow

The match number and "Most Recent" badges use absolute positioning outside the card box. Screen readers get the information through the updated `aria-label` on the article element, so the visual badges are supplementary. The concern is purely visual: in a context where the card is inside an `overflow-hidden` container (e.g., a scrollable panel, a card carousel), the badges would be clipped silently.
