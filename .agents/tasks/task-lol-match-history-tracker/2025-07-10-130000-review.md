# LoL Match History Tracker via Riot API proxy

A Next.js 16 App Router application that lets players search by Riot ID and view their 10 most recent League of Legends matches. The architecture is a server-side route handler (`/api/riot`) that proxies all Riot Games API calls, keeping the API key off the client. The frontend is a single client component page with a search form, match card grid, and error/loading states, all styled with Tailwind CSS v4 on a dark theme.

**Watch for:** Parallel fetch of 10 match details with no concurrency control or error isolation—one 429 or timeout tanks the entire request (confirmed). Hardcoded Data Dragon CDN version (`15.1.1`) will silently serve broken champion icons after the next game patch (confirmed). The `page.tsx` being a client component means the entire page ships as a client bundle with no server-rendered HTML for the initial state (likely).

## High-level view

The API layer is a single GET route handler that chains three Riot API calls: account lookup → match ID list → match details for each ID. Input validation is tight, error handling maps Riot status codes cleanly, and the API key never leaks to the client. The vulnerability is in the fan-out: `Promise.all` over 10 match detail fetches with no concurrency throttling and no partial-failure handling.

The frontend is a `"use client"` page that owns all state and wires a search form to the internal API. Marking the root page as a client component prevents Next.js from server-rendering the static shell (header, footer), which is a missed optimization for perceived load time. Semantic HTML and responsive Tailwind breakpoints are used correctly throughout.

The Data Dragon CDN version for champion icons is pinned at `15.1.1` in the route handler. This will break whenever Riot releases a new champion or reworks icon assets in a newer patch version. The fix is to fetch the latest version from the Data Dragon versions endpoint, or make it configurable.

<summary>Issues (5)</summary>

1. **Promise.all fan-out with no error isolation** — If any of the 10 `getMatchDetails` calls fails (429, timeout, network error), the entire request fails and the user sees nothing. Use `Promise.allSettled` and return partial results, or add concurrency limiting.
2. **Hardcoded Data Dragon version** — `15.1.1` in `route.ts` line 79 will produce broken champion icon URLs after the next Riot patch. Fetch the current version from `https://ddragon.leagueoflegends.com/api/versions.json` or make it configurable.
3. **Client component root page loses SSR shell** — The entire `page.tsx` is `"use client"`, so Next.js can't server-render the static header/footer. Extract a server component wrapper that renders the shell and embeds a client component for the interactive section.
4. **No request timeout on Riot API fetches** — `riotFetch` uses bare `fetch()` with no `AbortSignal` timeout. A hung Riot API response blocks the route handler indefinitely. Add a timeout (e.g., 10s per call).
5. **SearchForm splits only on first `#`** — `trimmed.split("#")` produces more than 2 elements if the input contains multiple `#` characters. Use `indexOf` + `slice` to split on the first `#` only.

## Riot API proxy and fan-out strategy

The route handler at `app/api/riot/route.ts` orchestrates three sequential stages: account lookup, match ID retrieval, and match detail fan-out. The first two are single requests; the third fans out to 10 parallel fetches via `Promise.all`.

```typescript
const matchDetails = await Promise.all(
  matchIds.map((matchId) => getMatchDetails(matchId))
);
```

Riot's development API keys have aggressive rate limits (20 requests per second, 100 per 2 minutes). Fetching 10 match details simultaneously after already spending 2 requests on account/match-IDs brings the total to 12 requests per user search. Two concurrent users will hit the ceiling. When the 429 fires on the 8th match, `Promise.all` rejects and the user gets zero results instead of 7 matches.

Switching to `Promise.allSettled` and filtering fulfilled results would give partial data gracefully. Alternatively, a simple concurrency limiter (batch of 3-4 at a time) would stay under rate limits for development keys.

There's also no `AbortSignal` timeout on any fetch call. A hung connection to Riot's API will hold the route handler open until the serverless function times out (typically 10-30s depending on hosting). Adding `signal: AbortSignal.timeout(10000)` to `riotFetch` is a straightforward fix.

## Hardcoded Data Dragon CDN version

The champion icon URL is constructed with a pinned version string:

```typescript
championIcon: `https://ddragon.leagueoflegends.com/cdn/15.1.1/img/champion/${championName}.png`,
```

Data Dragon versions correspond to game patches. When Riot ships patch 15.2 and adds or renames champion assets, images served from `15.1.1` may 404. The standard approach is to call `https://ddragon.leagueoflegends.com/api/versions.json` (returns an array, first element is latest) and cache the result for a few hours. This could live in the route handler as a module-level cached value or an environment variable.

## Client component page and SSR implications

The root `page.tsx` carries `"use client"` at the top, which means the entire component tree—including the static header, footer, and attribution text—ships as JavaScript and renders on the client. In Next.js App Router, the idiomatic pattern is to keep the page as a server component and extract interactive parts into client component children. The page shell (header, footer, empty main structure) would then be server-rendered HTML, improving first contentful paint.

## Input validation gap in SearchForm

The client-side validation splits on `#`:

```typescript
const [gameName, tagLine] = trimmed.split("#");
```

JavaScript's `split` without a limit returns all segments. A Riot ID input like `Player#Name#NA1` would destructure as `gameName = "Player"`, `tagLine = "Name"`, silently dropping `#NA1`. The server-side validation would then accept "Name" as a valid tagLine (2-4 chars).

Using `indexOf('#')` and `slice` would be more explicit about splitting on the first `#` only and would allow detecting the invalid case (multiple `#` characters).

## Unhandled JSON parse failure in riotFetch

If Riot's API returns a non-JSON response (maintenance pages, CDN errors), `response.json()` throws a `SyntaxError` that isn't a `RiotApiError`. This falls through to the generic 500 handler in the route, so the user sees "An unexpected error occurred" rather than a more actionable message. Low probability but worth a targeted catch if aiming for production polish.
